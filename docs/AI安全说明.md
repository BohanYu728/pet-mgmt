# 宠物管家助手 AI 安全

助手页面 `/ai/assistant` 展示默认开启的防护与三个可操作样例。按钮填入问题，点击“发送问题”后由后端返回检测结果。不能通过页面关闭安全检查。

后端在模型可用性检查、向量化与生成调用之前检查用户输入；使用 NFKC 和不可见字符处理，筛查常见中英文规则绕过、角色伪造、系统提示提取、疑似 API Key、密码、令牌、手机号和身份证号码。返回 `safety_blocked` 和 `input_blocked` 时没有调用模型，也不回显检测到的敏感内容。

项目知识片段同样先筛查；可疑片段不参与向量检索或原文降级展示。模型输出若含规则命中的风险内容会被隐藏，返回安全资料原文与 `output_blocked`。原有引用 ID 校验继续保留。通过规则检查不等于事实正确或完全安全。

助手只读取项目知识资料，不接入用户密码表、密钥配置或管理操作执行工具。身份认证、角色权限、Cookie 和 CSRF 由原有后端链路检查；提示词不能改变权限。云端凭据仍保存在后端环境配置，页面测试中的 Key 为明显标记的虚构文本。安全筛查不记录完整用户问题或匹配的敏感值。

这是多层防护中的规则筛查部分，覆盖范围有限：编码、多语言变体、间接诱导可能漏检，讨论风险指令的合法问题也可能误判。当前不宣称全量隐私识别、完整越狱防御或真实云端模型安全评测。应持续维护测试集，并结合来源核对、权限限制和人工复核。

参考：[OWASP Prompt Injection Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html)。

测试：`AssistantSafetyTest` 验证模型调用前拦截、普通密码帮助、输出风险隐藏、风险知识过滤、角色标记及个人信息边界；`scripts/verify-ai-safety.cjs` 验证真实页面、直接接口调用和手机布局。截图与结果位于 `docs/evidence/ai-safety/`。
