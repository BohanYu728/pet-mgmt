# 宠物管家系统：个人技能实训改造方案

## 1. 目标与范围

保留宠物管家系统的业务主题、业务模块、用户角色和已有数据，将 Java 版本改造为符合“第二部分 个人技能实训”五个实验要求的可运行项目，同时更新项目报告，并提供一份包含五个实验章节的综合实验报告。

主工程为 `pet-mgmt-java`。同级 `pet_mgmt_system` 是已有 Python 版本，保留作参考。课程实践方案原文件作为要求来源，不修改。原有 Word 报告保留，修订报告另存新文件。

业务范围：用户注册登录与个人资料；宠物档案；健康记录；疫苗与驱虫提醒；体重追踪；日常日志；相册；宠物医院与评价；商品浏览、购物车与订单；商户商品和订单管理；管理员用户、宠物和商户管理；品种识别、情绪分析、健康报告、商品推荐及症状咨询。新增基于项目资料的问答入口，仍围绕宠物管家业务。

“内容不变”以业务能力保留为准；页面名称、中文文案、已有图片和主要导航沿用，前端实现改为 Vue。已有业务如存在未接通的接口，纳入迁移与验收清单，不能只迁移页面外观。

## 2. 已核对的现状

- Maven 项目使用 Spring Boot 3.4.5，编译目标是 Java 21。
- 数据访问采用 Spring Data JPA，实体存在多处关联关系。
- 前端使用 Thymeleaf 和原生 JavaScript，尚非独立 Vue 工程。
- 已有宠物、商城、认证、管理、医院和 AI 等 REST Controller，适合复用业务逻辑并整理接口。
- 已有 BCrypt 和 JWT；前端 `main.js` 将令牌写入 localStorage。
- 安全配置关闭 CSRF；部分公开路径未区分 HTTP 方法，需要检查写入接口权限。
- 用户实体以 role 字段表示角色，尚需增加明确的角色、权限及关联表。
- 已有兼容 OpenAI 协议的 HTTP 调用和本地降级逻辑；已读咨询实现没有完整的“切块—向量化—检索—引用”链路。
- Java 工程当前不属于 Git 仓库；需要建立版本管理、分支和 CI 配置。
- 本机可找到 Java、Maven、Node.js、npm 和 Git。实际构建、数据库连接及浏览器联调尚未执行，不能据此宣称项目运行正常。

## 3. 技术路径比较

### A. 在现有 Java 工程上渐进改造（推荐）

复用领域模型、业务服务和资产；新增独立 Vue 工程；整理 REST API；补充实训所需 MyBatis 用户 CRUD、RBAC、CI 和 RAG。其余业务暂保留 JPA，避免为更换 ORM 大范围重写关联查询。报告明确两者的职责边界。

优点：最有利于保留业务和数据，同时覆盖实验要求。代价：需清晰管理 JPA 与 MyBatis 共用数据源时的映射和事务，不能让同一项写入被两套逻辑重复处理。

### B. 全面重写为 Spring Boot + MyBatis + Vue

所有持久层和前端重写。技术栈统一，但迁移关联、业务规则与数据的工作量和回归风险显著更高；本次不推荐。

### C. 另建独立实训示例项目

实施较快，但会使原系统与实验成果脱节，不满足“修改项目代码并同步更新报告”的选择；本次不采用。

后续按 A 分阶段实施，每阶段必须通过相应验收后再继续。

## 4. 实验一：Web 基础项目

- Maven 编译目标调整为 JDK 17；检查现有代码是否使用 Java 21 专属 API，并替换不兼容用法。
- 保留 Spring Boot 3.x 与 MySQL，增加兼容的 MyBatis starter。
- 用户管理使用 Entity/DTO、Mapper、Service、Controller 分层，完成管理员用户新增、列表/详情、修改和删除。
- 复用 users 表，不建立一套互不关联的“实验用户”。密码只保存 BCrypt 哈希，返回 DTO 不包含密码哈希。
- 删除存在业务关联的用户时给出明确处理规则，默认拒绝会造成业务数据丢失的删除；不以级联清空原数据作为实验捷径。
- 配置从环境变量读取数据库凭据，提供无真实密钥的配置示例。保留可复现的开发、测试启动说明。
- 数据库结构变更以显式迁移脚本实现，新增表和关联不清空现有数据。

验收：在测试数据库上验证用户 CRUD、重复用户名/邮箱、无效字段、关联数据删除限制和密码哈希；执行 Maven 测试及 jar 打包。

## 5. 实验二：Vue 与 REST API

- 新增 `frontend`：Vue 3、Vite、Vue Router、Axios。
- Vue 负责页面路由和交互；后端返回 JSON；前后端分别构建和启动。
- 复用现有 CSS、图片和中文业务内容；逐个迁移原有页面与业务流程，不用嵌入旧网页代替 Vue 实现。
- 接口统一使用 `/api` 前缀、明确的 HTTP 方法、请求 DTO、分页参数及错误结构。旧接口是否保留兼容别名以迁移需要为准。
- 配置开发和部署环境的 CORS 白名单；带凭据请求不得使用任意来源通配符。
- 增加 OpenAPI 文档，并核对字段、权限、上传格式、分页和异常响应。
- Vue 对 400、401、403、404、409 和服务不可用给出明确反馈。

验收：前端构建；浏览器验证登录、宠物 CRUD、健康/提醒/体重/日志/相册、商城下单、商户与管理员流程、原有 AI 页面；保存真实截图。

## 6. 实验三：Git 与 CI

- 增加 `.gitignore`，排除凭据、上传文件、构建输出、依赖目录及本机运行数据。
- 建立 Git 基线和 `feature/personal-training` 分支，以可审查的小步提交记录改造。
- 增加 PR 模板，包含改动范围、验证证据、AI 辅助评审和人工评审栏目。
- GitHub Actions 执行 Java 17 后端测试与打包、前端依赖安装、测试和构建。
- 提供独立练习目录或临时分支上的冲突演示步骤，不制造主工程冲突来冒充协作成果。
- AI 可提供初步审查意见；人工审查记录必须由真实参与者完成。

验收：本地执行 CI 中对应命令，核对工作流配置。远程推送、真实 PR 和云端 Actions 运行需要用户指定仓库及可用权限；未发生时在报告中标记为未完成，不伪造链接、截图或协作记录。

## 7. 实验四：登录、RBAC 与 AI 安全

- 保留普通用户、商户、管理员角色；增加 roles、permissions、user_roles、role_permissions 等表，并从现有 role 字段迁移关联。
- 使用 Spring Security 与 `@PreAuthorize` 验证权限，同时在业务层检查对象归属。用户不得读取或修改其他用户宠物、记录及订单；商户只能管理自己的商品和订单。
- JWT 放入 HttpOnly Cookie，生产环境启用 Secure，并配置适当的 SameSite。前端不在 localStorage/sessionStorage 中保存令牌，也不把令牌返回到可读的页面状态。
- Cookie 认证配套 CSRF 防护；提供 CSRF 获取流程、Axios 请求头处理、退出清除 Cookie 和过期处理。
- 密码使用 BCrypt 单向哈希；JWT 签名密钥和模型 API Key 从环境变量读取，不写入源码、报告、浏览器或数据库。需要持久保存的其他秘密须采用专用密钥管理或加密方案。
- AI 输入限制长度和格式；用户输入、检索资料与 System 指令明确分离。检索材料视为不可信内容，不给予修改系统规则的权限。
- 模型不能执行任意工具、SQL、文件读写或泄露密钥；不宣称关键词过滤可以完全消除提示注入。

验收：未登录、角色越权、跨用户访问、CSRF 缺失、过期/篡改 JWT、登出，以及提示注入样例；检查浏览器存储及 API 响应不暴露令牌或秘密。

## 8. 实验五：LLM 与 RAG

- 提供统一 LLM 客户端，配置兼容 OpenAI 协议的地址、模型和 API Key；按选定 SDK 实现调用与超时、错误处理。
- 封装 `ask(question)` 应用服务，使用明确的 System/User 消息和稳定的结果结构。
- 将随项目附带的操作说明、功能说明等资料按段切块，保留文件、章节和块编号。
- 使用可配置 embedding 模型获取向量，执行相似度检索，再将相关片段作为不可信参考上下文发送给对话模型。
- 资料不足时明确回答无法根据现有资料确认；答案展示出处，后端校验引用编号是否属于本次检索结果。
- Vue 增加“宠物管家助手”入口；原有品种、情绪、健康报告、推荐和咨询入口继续保留。
- 模型未配置或服务不可用时显示真实状态，可以展示检索资料或原有本地降级结果，但不得把本地规则输出标注成大模型成功调用。
- 基于养宠资料的回答不冒充真实兽医诊断。记录实际观察到的幻觉/失败案例，以及上下文限制、引用和人工核查方法。

验收：切块、向量相似度、无相关资料、引用校验、注入文本和模型超时测试；模拟服务验证协议交互；仅在有可用真实模型时记录真实 API 与 embedding 联调成功。
